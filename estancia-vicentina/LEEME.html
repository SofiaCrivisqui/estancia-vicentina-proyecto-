Estancia Vicentina
Guía de uso y entrega

Tres páginas en HTML, CSS y JavaScript. No requiere Node, instalación de paquetes, compilación ni una base de datos para mostrar el sitio.

Abrir la web → · Abrir el editor →

1. Empezar

  1. Descomprimí el ZIP completo.
  2. Abrí index.html con doble clic. Las tres páginas, imágenes y menú funcionan localmente.
  3. Si usás Visual Studio Code, podés abrir la carpeta con Live Server.

2. Cambiar textos y datos sin programar

  1. Abrí EDITOR.html.
  2. Cambiá los textos, teléfono, correo o enlaces.
  3. Presioná “Descargar configuración actualizada”.
  4. Reemplazá configuracion.js por el archivo descargado. Si el navegador le agregó “(1)”, renombralo exactamente a configuracion.js.
  5. Recargá la web. Si está publicada, subí ese archivo al hosting y recargá con Ctrl+F5.

Los textos principales están en el editor. Los rótulos de navegación, campos, integrantes y cifras de distancias están en los HTML, identificados por sus etiquetas. El editor conserva los cambios solo cuando descargás y reemplazás el archivo.

3. Cambiar imágenes

Reemplazá el archivo dentro de assets/images/ manteniendo nombre y formato WebP. No renombres una foto JPG a WebP: exportala al formato correcto. También podés actualizar la ruta en el HTML.

4. Plano definitivo

El actual es el plano de la maqueta, señalado como provisorio. Reemplazá la imagen o cambiá su ruta en el editor. Desmarcá “Mostrar aclaración de plano provisorio” cuando lo aprueben. El plano puede ampliarse al hacer clic; no simula stock ni disponibilidad en tiempo real.

5. Formularios y newsletter

Esta entrega incluye el frontend y las validaciones. El envío real requiere conectar un backend; no incluye PHP, SMTP ni credenciales. Hasta conectarlo, el sitio informa que el envío web no está disponible y ofrece el correo de contacto. Nunca muestra un éxito ficticio.

El programador configura las URL de envío en configuracion.js. La documentación del contrato y los eventos está en docs/INTEGRACION.md. Newsletter usa su propio endpoint, sin suscribir contactos automáticamente.

6. Meta Ads y Google Ads

Los botones y formularios ya exponen eventos. Se usa un único contenedor de Google Tag Manager para instalar GA4, Google Ads y Meta Pixel, evitando duplicaciones. El ID queda vacío hasta que se disponga de la cuenta. Al configurar un ID válido se habilita el control de consentimiento; no se cargan etiquetas antes de aceptar.

El programador debe crear las etiquetas y conversiones dentro de GTM y probarlas con las cuentas reales. Los clics de WhatsApp son intenciones; los leads se registran únicamente tras la confirmación del servidor.

7. Publicación

Subí index.html, loteo.html, contacto.html, configuracion.js y la carpeta assets a un hosting con HTTPS. No hace falta subir el editor ni la documentación. Configurá el dominio en el editor para completar las URL canónicas e imagen social. Las rutas relativas permiten usar una subcarpeta.

8. Qué falta confirmar

  • Plano definitivo y disponibilidad.
  • Enlaces reales de redes y LinkedIn: se ocultan mientras estén vacíos.
  • Backend de formulario/newsletter y sus validaciones de servidor.
  • ID GTM y etiquetas de las cuentas publicitarias.
  • Dominio y configuración de hosting.

Se usaron los recursos de los PDF entregados, incluidas sus fuentes. Para publicación, el titular debe disponer de las licencias web correspondientes; puede reemplazar los archivos de fuente por los originales licenciados. Las fichas no entregadas de Lotes Encuentro y Reserva no se inventaron. Los puntos de carrusel de las maquetas se omitieron porque no se entregaron las otras diapositivas. Los paneles cerrados usan breves textos de apoyo derivados del contenido del proyecto, editables y sujetos a aprobación.
